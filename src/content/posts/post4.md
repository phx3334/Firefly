### 系统级和用户级定时任务对比

| 对比维度 | 系统级 | 用户级 |
| --- | --- | --- |
| 位置 | `/etc/crontab`（主配置）、`/etc/cron.d/`（附配置） | `crontab -e` |
| 实际存储 | `/etc/crontab` | `/var/spool/cron/crontabs/用户名` |
| 需写用户名 | 必须写 `user /path/script` | 不需要 |
| 权限 | root 执行 | 对应用户执行 |
| 管理 | 管理员统一管理 | 用户自己管理 |
| 适用 | 系统维护、全局服务 | 个人脚本 |

### 定时任务的时间书写规则
```text
分  时  日  月  周  命令
*   *   *   *   *   command
│   │   │   │   │   └── （用户名） /path/script
│   │   │   │   └── 周几 (0-7, 0和7都是周日)
│   │   │   └──── 月份 (1-12)
│   │   └─────── 日期 (1-31)
│   └────────── 小时 (0-23)
└───────────── 分钟 (0-59)
```
#### 举例
```bash
# 每分钟执行
* * * * *
# 每5分钟执行
*/5 * * * *
# 每小时整点执行
0 * * * *
# 每天凌晨2点执行
0 2 * * *
# 每周一凌晨3点执行
0 3 * * 1
# 每月1号凌晨4点执行
0 4 1 * *
# 工作日早9点执行
0 9 * * 1-5
# 每小时的第15分和第45分执行
15,45 * * * *
# 上午9点到下午5点每小时执行
0 9-17 * * *
# 每年1月1号凌晨0点执行
0 0 1 1 *
```


### FAQ

#### 1.为什么定时任务文件是引用其他文件写好的脚本内容进行执行？

答：因为定时任务的环境变量极少（只有 HOME, LOGNAME, PATH 等几个）脚本里出问题很难排查；  
而且 % 号是 cron 的特殊字符；  
独立脚本可以单独跑，调试方便。  

#### 2.为什么系统级定时任务要指定用户？

答：系统级 crontab 只有 root 能编辑，但任务不一定要 root 执行。必须显式指定用户名，目的是以最小权限运行任务，避免一个脚本漏洞导致整个系统沦陷。  
    用户级 crontab 是用户自己编辑的，默认就是自己执行，不需要再写用户名。
