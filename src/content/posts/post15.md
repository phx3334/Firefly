## 分层思想
网络故障排查的核心方法是**分层排除法**：按照四层模型（链路层 → 网络层 → 传输层 → 应用层），从最近的本机开始，一层一层往外测，**每层都通了再测下一层，哪一层断就锁定在哪一层**。不要一上来就抓包或玄学。  
排查前先收集信息，避免瞎猜：
- **问题现象**：完全不通？时通时断？很慢？特定端口不通？特定来源不通？
- **影响范围**：只有你访问不了，还是所有用户都访问不了？
- **时间点**：什么时候开始？改过什么配置/发过什么版本？
> 这一步决定排查方向。例如"只有外网访问慢"和"内网也不通"是完全不同的问题。
```bash
#查看的是网卡设备本身信息，可以理解为是数据链路层
ip link
#简写ip s,查看网卡上绑定的ip地址，广播，作用域等，可以理解为是网络层
ip addr
#查看哪个端口正在被监听，哪个端口运行什么进程。可认为是传输层
ss -tlnp
#查看域名解析信息，可以认为是应用层
dig www.example.com  
```

## 链路层：网卡与物理链路
**症状**：完全不通、网卡灯不亮、`ip a` 里网卡状态异常。
```bash
ip link                        # 查看网卡的各种状态信息，例如是否up,mtu,mac值（ip link show 网卡）
ip -s link                     # 看统计：RX（收包）/TX（发包） 错误、丢包是否暴增
ethtool eth0                   # 看网卡硬件层面的问题。例如Link detected: no。协商速率（带宽）
dmesg | grep -i -E "eth|link"  # 看内核日志有没有网卡报错
```
**判断标准**：
- `state DOWN` → 网卡没启用：`nmcli con up 网卡`
- `Link detected: no` → 物理线路问题（网线、光模块、交换机端口、VLAN）
- RX/TX errors 大量增长 → 网线质量差、速率不匹配、交换机问题

## 网络层：IP 配置与路由
**症状**：`ip a` 看不到 IP、IP 不对（如 `169.254.x.x` 是没拿到 DHCP 的链路本地地址）。
```bash
ip addr show eth0              # 看 IP/掩码是否配置正确
ip route                       # 看路由表是否存在、默认网关是否正确（网络层核心）
traceroute -n 目标IP           # 网络层：打印每一跳路由及耗时，定位断/慢在哪一段
mtr -n 目标IP                  # 网络层：traceroute+ping 合体，持续看每一跳丢包率
cat /etc/resolv.conf           # 看 DNS 配置
```
**判断标准**：
- 没有 IP → DHCP 没拿到（`nmcli con up` 重新获取）或静态配置丢失
- IP 是 `169.254.*` → DHCP 失败，检查 DHCP 服务器/网段
- 默认路由缺失 → 网关配置问题（`ip route` 里看不到 default）
- 路由都对但目标不通 → `traceroute -n 目标IP` / `mtr -n 目标IP` 看断在哪一跳
### 逐层连通性测试（核心）
从"最近的"开始，一层层往外 ping，**哪一层断就锁定在哪一层**：
```bash
# ① 回环接口：测本机协议栈是否正常
ping 127.0.0.1

# ② 自己的 IP：测网卡收发是否正常
ping 192.168.1.5

# ③ 网关：测局域网内部是否通（不通→内网/交换机/VLAN 问题）
ping 192.168.1.1

# ④ 公网 IP：测路由和出网是否通（不通→网关/路由/NAT/ISP 问题）
ping 8.8.8.8

# ⑤ 域名：测 DNS 解析是否正常（前 4 步通但这里不通→DNS 问题）
ping www.baidu.com
#查看从本机到8.8.8.8的路由情况。通过这个命令可以看到每一跳路由器（网关）的ip,该跳的丢包率，延迟等信息（mtr是可以动态观察的）
mtr -n 8.8.8.8

```
**关键判断**：
- ①、② 不通 → 本机问题（网卡/协议栈/防火墙）
- ③ 不通 → 内网问题（网关、交换机、VLAN）
- ④ 不通 → 路由/NAT/出口问题（先用 `ip route` 看默认路由在不在，再用 `mtr` 看断在哪一跳：网关后第一跳就断→运营商/出口问题；中途某跳丢包暴涨→该段链路质量差）
- ⑤ 不通但 ④ 通 → **DNS 问题**（第 4 层详查）
> 注意：有些服务器会禁 ICMP（ping），所以 ping 不通**不一定**是网络不通。用 `telnet 目标IP 端口` 或 `curl` 验证更可靠。

## 传输层：端口、服务与防火墙
**症状**：网络通，但连不上某个服务（SSH、数据库、网站）。
```bash
# 本机：服务是否在监听？哪个进程占用？
ss -tlnp

# 远程：目标端口通不通？（通=连接成功；不通=连接拒绝或超时）
telnet 目标IP 3306

# 主要看services: 和 ports这2行，前者展示放行了哪些预定服务，例如ssh,https，mysql等,后者展示放行了哪些裸端口，例如3306/tcp.
firewall-cmd --list-all     
#主要看 chain input(入方向链)里的规则，
nft list ruleset            
```
**判断标准**：
- `ss -tlnp` 里没有该端口 → 服务没起来或监听在其他网卡（如只监听 127.0.0.1）
- telnet 显示 `Connection refused` → 端口没监听或防火墙**明确拒绝**
- telnet 一直卡住/`timed out` → 防火墙 DROP 或中间链路问题
- 本机能连、外网不能连 → 检查防火墙、**云厂商安全组/防火墙规则**

## 应用层：DNS 与服务日志
### DNS 解析排查
**症状**：能 ping 通 IP，但域名访问失败。
```bash
#status（HEADER 里）— 解析是否成功，ANSWER SECTION — 域名解析到的最终 IP，Query time — 解析耗时，SERVER — 实际响应的是哪台 DNS 服务器
dig www.example.com                   
cat /etc/resolv.conf                  # 确认 DNS 配置
```
**常见原因**：`/etc/resolv.conf` 被覆盖、DNS 服务器不可达、DNS 服务器只配置了一个且它挂了。

### 抓包分析（最底层定位）
**适用**：前几层都查不出，或怀疑"数据到底有没有出去/回来"。
```bash
# 抓目标主机的流量，看有没有 SYN 发出、有没有响应（抓取源或目标是8.8.8.8的所有包）
tcpdump -i eth0 -nn host 8.8.8.8

# 抓端口流量（源端口或目标端口是 3306 的包）
tcpdump -i eth0 -nn port 3306

# 抓完整包存文件，交给 Wireshark 分析（-s 0表示抓取完整包，默认只抓96字节包头部）
tcpdump -i eth0 -nn -s 0 -w /tmp/capture.pcap

#tcpdump抓包输出的数据：
#抓到包时的时间戳，网络层协议，源地址，目标地址
#标志位。Flags[S]=SYN,[S.]=SYN+ACK、[.]=ACK、[P]=数据、[R]=RST、[F]=FIN
#seq序号。接收窗口大小。TCP协商参数，例如MSS=最大报文段
#length代表负载字节数，0代表纯控制包，无数据
```
**典型结论**：
- 看到 SYN 发出但**没有响应** → 包出去了，回来被丢（防火墙、安全组、路由回程问题）
- 连 SYN 都没发出 → 本机路由/防火墙把包拦了
- 看到 `RST` → 对方主动拒绝（端口没开或被防火墙 REJECT）

## 补充排查：资源负载与外部因素
### 系统资源与高负载
**症状**：时通时断、延迟高、连接超时。
```bash
# 看所有连接数
ss -s
#筛选出TCP协议的连接中已经建立连接的
ss -tn state established | wc -l

# 查看cpu负载（负载高导致响应慢）
top
#查看所有网卡的实际带宽
nload 
```
**常见原因**：`net.core.somaxconn（内核配置的半连接队列大小，实际应用大小大小看backlog）` 太小、进程文件描述符耗尽（`ulimit -n`）、带宽被占满、CPU 100%。

### 云厂商/外部因素
**适用**：本机全部正常，但外部还是访问不了。
- **云安全组（Security Group）**：入站/出站规则是否放行对应端口（最容易漏的一环）
- **云防火墙 / WAF / DDoS 防护**：是否误拦
- **备案问题**：国内服务器未备案会拦截 80/443 访问
- **运营商/ISP**：境外访问国内、线路拥塞
- **CNAME/域名解析**：DNS 有没有解析到正确 IP（`dig 域名`）


## 总结

| 层 | 常见错误 | 大致定位方向 |
|----|----------|-------------|
| 链路层 | 网卡未启用、物理线路断（网线/光模块/交换机端口）、RX/TX 错误暴增 | 本机网卡状态 → 物理链路 → 交换机端口/VLAN |
| 网络层 | 没有 IP 或拿到 169.254、IP/掩码配错、默认路由缺失、断在路径中某跳 | 本机 IP 配置 → 网关 → 逐跳路径（出口/运营商/对端） |
| 传输层 | 服务没监听或只监听本机、防火墙拦截（拒绝/超时）、安全组未放行 | 本机监听状态 → 本机防火墙 → 云安全组 |
| 应用层 | DNS 解析失败（域名能 ping 通 IP 但访问不了）、服务本身报错 | DNS 配置/服务器 → 服务日志 |
| 资源/外部 | 连接数爆满、CPU/负载过高、带宽打满、云安全组/WAF/备案/ISP 限制 | 连接数 → 负载 → 带宽 → 云厂商/运营商侧 |

**核心心法**：永远先"逐层排除法"——从最近的本机开始，一层层往外测，每层都通了再往下一层，哪层断就锁定在哪层。
