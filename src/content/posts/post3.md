## 1. 基本原理

### 1.1 ssh基本原理
ssh是加密的远程登录协议，所有数据加密传输。我们一般采用密钥方式进行ssh连接，这样更加安全且方便。
下面是ssh连接过程

#### 准备阶段
ssh通过命令生成私钥和公钥
```bash
#rsa是加密方式，4096是密钥长度，默认1024
ssh-keygen -t rsa 4096
```
客户端将公钥给要远程连接的服务器
```bash
#将公钥追加到服务器的~/.ssh/authorized_keys文件中
ssh-copy-id -i ~/.ssh/id_rsa.pub user@192.168.1.100
```

#### 连接建立阶段（非对称加密）

客户端发起 TCP 连接到服务端 22 端口

双方协商加密算法，确定用哪种方式加密

服务端发送自己的主机公钥给客户端

客户端对比 ~/.ssh/known_hosts 中保存的指纹，确认服务端身份可信

双方通过 DH 密钥交换算法，各自计算出相同的会话密钥

此密钥只用于本次连接，用完即废

#### 身份认证阶段（非对称加密）
客户端声明用密钥方式登录

服务端在 ~/.ssh/authorized_keys 中查找对应的公钥

服务端生成随机数，用该公钥加密后发给客户端

客户端用自己的私钥解密随机数，签名后发回

服务端用公钥验证签名，一致则认证通过

#### 远程操作阶段（对称加密）
后续所有数据都用会话密钥对称加密传输

敲的命令、返回的结果、传输的文件，都走这条加密通道

对称加密速度快，CPU 开销小，连接保持高效


## 2. 常用命令

### 2.1 ssh常用命令
```bash
#指定服务器监听端口21333（默认22），远程连接192.168.1.100服务器上的user用户，并依次执行后面那三个命令
ssh -p 21333 user@192.168.1.100 "hostname;pwd;whoami"
#~/.ssh/id_rsa.pub为默认公钥路径，该命令将公钥自动追加到user用户的~/.ssh/authorized_keys文件中，以后 ssh 登录不需要密码
ssh-copy-id -i ~/.ssh/id_rsa.pub user@192.168.1.100
```
### 2.2 scp常用命令
```bash
# 上传单个文件
scp local.txt user@192.168.1.100:/tmp/
# 上传并改名
scp local.txt user@192.168.1.100:/tmp/newname.txt
# 上传整个目录
scp -r dir/ user@192.168.1.100:/tmp/
#-p参数保留文件元数据
scp -rp dir/ user@192.168.1.100:/tmp/
#将远程服务器的文件下载本地服务器的aa.txt里面
scp root@192.168.1.100:/etc/hosts ./aa.txt
#将hosta服务器的文件上传到hostb服务器的/path/目录下(不经过本地中转，逻辑上由ssh隧道支持)
scp root@host1:/path/file root@host2:/path/
```
### 2.3 配置文件
```bash
#记录你连接过的所有服务器主机名和公钥指纹。
~/.ssh/known_hosts
#该文件夹下有你的私钥文件（默认位置）
~/.ssh
#SSH 服务端（sshd）的各种行为配置
/etc/ssh/sshd_config
```

## 3.ssh端口转发
### 什么是跳板机（jump-host）
生产环境的安全惯例是：内网的服务（数据库、K8s、后台）不直接暴露公网，公网上根本连不到。但你作为运维又得去操作它们。于是：
- 只把一台 hardened（加固过的）服务器放开公网 SSH 访问，叫 jump-host。
- 所有内网服务只对这个 jump-host 开放，不对公网开放。
- 你先 SSH 连到 jump-host，再从它出发去连内网。
### 本地转发-L
洞口开在你本地，目标在远端网络。本地应用连本地端口 → 数据进 SSH 管道 → 服务端从管道取出 → 去连远端目标 → 响应原路返回。  
```bash
#-N表示不执行远程命令，只建立隧道
ssh -N -L 3306:10.0.0.5:3306 user@jump-host
```
例如你借助本地转发，可以用自己的电脑连上公司的内网的数据库服务器，借助一些数据库的图形化软件，用127.0.0.1:3306，输入数据库密码就能看到数据库的内容了。
### 远程转发 -R
洞口开在远端服务器上，目标在你本地网络。别人连远端服务器的端口 → 数据进 SSH 管道 → 你本机从管道取出 → 去连本地目标 → 响应原路返回。  
```bash
ssh -N -R 8080:localhost:80 user@public-server
```
例如你有一个个人博客运行在自己本地内网电脑上，想要让你的朋友通过公网访问，那么你可以借助一个公网ip的云服务器（1.2.3.4），将该云服务器的sshd_config中的GatewayPorts确定为yes，然后你在本地电脑上用上述建立与云服务的隧道。此时你的朋友可以通过http://1.2.3.4:8080来访问你的博客。
**GatewayPorts** ：决定这个转发端口监听在服务器的哪个地址上，no->只监听 127.0.0.1，公网访问不到,yes->监听 0.0.0.0，公网才能访问
### 动态转发 -D
洞口开在你本地，但不指定具体目标，而是在本地开一个 SOCKS5 代理端口。本地应用把流量交给这个代理 → 数据进 SSH 管道 → 服务端替你去访问任意目标 → 响应原路返回。适合一条隧道访问内网的多个服务。  
```bash
ssh -N -D 1080 user@jump-host
```
例如你借助动态转发，把浏览器（或使用 curl 等工具）的代理设置成 127.0.0.1:1080（SOCKS5），就能通过浏览器像身在公司内网一样浏览内网网页、访问多个内网系统，不用每访问一个服务就开一条隧道。  


## vpn
### vpn基本原理
VPN（Virtual Private Network，虚拟专用网络）是在公共网络上建立一条加密的"专用隧道"，让数据像在私有网络中一样安全传输。三大核心要素：
- **隧道**：把原始数据包整体封装成新数据包，再走公网传输
- **加密**：隧道内的数据用对称密钥加密，防窃取、防篡改
- **认证**：确认客户端和服务器双方身份，防中间人攻击
工作流程：客户端创建虚拟网卡 → 应用流量被虚拟网卡截获 → 封装 + 加密 → 经公网发给 VPN 服务器 → 服务器解密、解封装后转发到目标地址，回包反向同理。
### 场景例子：用VPN“翻墙”
#### 前置
##### CDN
CDN（Content Delivery Network，内容分发网络）把网站的静态内容（图片、视频、JS、CSS 等）提前复制到全球各地的服务器上（源服务器会依情况再提前复制某些后端数据给分发服务器），让用户从"离自己最近的服务器"获取，而不是每次都跑到源服务器。
**过程** ：访问网站时，先做 DNS 解析，CDN 服务商（如 Cloudflare）在全球部署了成千上万个节点，每个节点有不同 IP，cloudflare的权威DNS服务器（分布在全国各地）解析时，根据你所在的地理位置，返回"离你最近的那个节点"的 IP，所以你在国内，DNS 就给你返回国内（或附近地区）的 Cloudflare 节点 IP。  
##### 国内大防火墙规则（猜测）
基于公开学术研究与技术观察推测，规则不是"一刀切禁境外"，而是**名单制 + 特征制 + 行为制**三层叠加、动态更新：
- **名单制（精准拦截）**：域名黑名单 + IP 网段黑名单，命中即拦截
- **特征制（识别隐藏）**：TLS/SNI 检测、VPN 协议指纹识别，针对藏在加密/CDN 后面的目标
- **行为制（动态兜底）**：异常流量模式（如大量连接境外节点），补充前两层的盲区
对应到真实网络行为，大致是：
| 检测点 | 看到的特征 | 拦截动作 |
|---|---|---|
| DNS 查询 | 域名命中名单 | 返回伪造 IP（污染），连不上 |
| IP 层 | 目标 IP 命中名单 | 静默丢弃（黑洞） |
| TCP 握手 | 目标 IP:端口命中 | 伪造 RST 包强制断开 |
| TLS 握手 | SNI 字段（明文域名）命中 | 丢包 / RST |
| 加密流量 | 疑似 VPN 协议特征 | 限速 / 阻断 |
**特点**：名单持续更新、可多层叠加；只针对名单内目标，正常境外网站（GitHub 等）不在名单但仍会受线路影响（见补充）。
#### 用VPN“翻墙”的过程
假设本地网络对某些境外网站做了访问限制（俗称"翻墙"），直接访问会失败。用 VPN 的完整过程如下：  
0. **准备**：将从网站上获得的一段链接（对应连接配置单,包括连接的协议类型，服务器ip,端口，密钥，数据加密方式等）复制到客户端（clash）
1. **建立隧道**：本地运行 VPN 客户端，与境外 VPN 服务器完成认证和密钥协商，建立加密隧道
2. **捕获流量**：浏览器请求 `example.com`，数据包被虚拟网卡截获
3. **封装加密**：原始数据包整体被打包加密，外层目标 IP 是 VPN 服务器
4. **穿透封锁**：网络防火墙只看到"你在访问一台境外服务器"的加密流量，无法识别真实内容，放行
5. **代你访问**：VPN 服务器解密、解封装，以它自己的 IP 向 `example.com` 发起真实请求
6. **原路返回**：目标网站响应发给 VPN 服务器，服务器封装加密后回传，本地解密，浏览器正常显示页面
**注意**：隧道内数据对防火墙不可见，但 VPN 服务器可以看到你的真实目标地址和全部内容，所以"加密"不等于"匿名"，选 VPN 服务商要谨慎。
**补充** ：
- **连接是怎么建立的**：不是虚拟网卡自己连服务器，而是客户端程序先通过真实网卡向 VPN 服务器握手认证（验证密码/证书 + 协商对称密钥），成功后才创建虚拟网卡并写入路由表接管流量
- **虚拟网卡的作用**：一个软件模拟的网络接口——截获应用的原始 IP 包交给客户端程序封装加密；把解密后的回包注入系统网络栈，应用无感知
- **为什么防火墙会放行**：防火墙只看到外层：源 IP 是你、目标 IP 是 VPN 服务器、端口 443，像普通 HTTPS；内层真实目标被加密不可见。注意这只是"伪装"而非"隐形"，严格审查可通过流量特征识别
- **为什么不用 VPN 访问 GitHub 是概率事件**：GitHub 不在封锁名单，但它没有国内 CDN 节点、国际线路拥堵绕路、IP 池质量参差，每次连接走的路由和 IP 不同 → 时通时不通。VPN 把这些"看运气"的链路替换成固定且质量好的链路，所以变稳


## ssh和vpn的主要应用场景
### ssh的应用场景
- **远程管理服务器**：登录 Linux 服务器执行命令、部署、排障，是最主要的用途
- **文件传输**：scp / sftp 在服务器间安全传文件
- **端口转发**：访问内网服务（数据库、后台）不暴露公网
- **git 推送/拉取**：github 等代码仓库走 ssh 协议认证和传输
### vpn的应用场景
- **企业远程办公**：员工在外网连回公司内网，访问内部系统像在办公室一样
- **站点互联**：分公司局域网之间通过 VPN 网关互通（Site-to-Site）
- **公共 WiFi 安全**：机场/酒店等不可信网络下，VPN 加密你的全部流量，防窃听
- **访问被封锁/不稳定的境外网站**：通过加密隧道绕开网络层限制（前面"翻墙"场景）
### 场景对比
| 场景 | 用 ssh | 用 vpn |
|---|---|---|
| 登录服务器执行命令 | ✅ 首选 | ❌ 杀鸡用牛刀 |
| 只传一个文件 | ✅ scp | ❌ 过度 |
| 访问公司内网多个服务 | ⚠️ 可用 -D 动态转发 | ✅ 系统级全接管 |
| 浏览器等所有应用翻墙 | ⚠️ -D 代理配置繁琐 | ✅ 开即用 |
| 公共 WiFi 防窃听 | ❌ 只保护 ssh 连接 | ✅ 全部流量 |
**选择原则**：只访问一台服务器 → ssh；要让整个系统"像接入了某个网络" → vpn。


## FAQ
### 为什么密钥认证比密码登录安全且方便
**更安全**：
- 密码会在网络传输，易被暴力破解、撞库、钓鱼；私钥全程留在本地，不出本机
- 服务器只保存公钥，即使服务器被攻破，也无法反推出私钥
- 4096 位随机密钥的强度远高于人为设置的密码
**更方便**：
- 配置一次，以后登录免输密码，还可在 ssh 命令里直接跑远程脚本
